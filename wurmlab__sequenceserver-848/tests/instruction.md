# Issue

**Title:** Quote database_dir for blastdbcmd and fix ignored keys in report spec

## Description

## Summary

Two small fixes found while running `bundle exec rspec` locally.

**Database directories with spaces broke startup.** The path passed to `blastdbcmd -recursive -list` in `lib/sequenceserver/makeblastdb.rb` was interpolated into the shell command unquoted. A directory such as `sequenceserver-master 2` made blastdbcmd fail with `Too many positional arguments (1), the offending value: 2/spec/database/v5`, so every spec that calls `SequenceServer.init` failed (92 failures in a checkout under such a path). The same failure hits any user whose database directory contains a space. The path is now escaped with `Shellwords.escape`.

**Report spec compared the version despite meaning to ignore it.** `spec/blast/report_spec.rb` lists keys to skip when comparing against the `frontend.json` fixture, including `seqserv_version`. The list used symbols while `JSON.parse` returns string keys, so nothing was ever skipped and any version bump failed the spec (`expected: "3.1.3", got: "3.2"`). The list now uses string keys.
