# Issue

**Title:** [FIX] Percolator spline: keep every entry of g after the general IRLS step (SIGTRAP on macOS)

## Description

## Description

 (`Percolator_test` fails with SIGTRAP on macOS with the Nix build).

**Cause.** `BaseSpline::iterativeReweightedLeastSquares` builds `gnew` on its general path (when the banded fast path does not apply) as `z.packedSubtract(aWiQ.packedMultiply(gamma))`. The packed (sparse) vector operations leave out entries with |value| ≤ 1e-15. The spline code then reads `g` **by position**: `evaluateSlope`, `splineEval`, `LogisticRegression::calcPZW` and `limitg`. `evaluateSlope` even notes `//This should be a filled vector`. So:
- a dropped entry shifts all later values;
- an all-zero `g` has no entries at all, and `evaluateSlope` reads `g[1]` of an empty vector.

The second case happens in the section `[EXTRA] nonparametric PEP with fewer than 4 distinct scores` (data padded to 4 bins, `x = {-3, -1, 3, 9}`, `g` with 0 entries). Builds without bounds checks read stale memory within the vector's capacity and pass. libc++ hardening, which nixpkgs enables by default for clang/libc++, traps there, which shows up as SIGTRAP on macOS.

Reproduced on Linux with g++ 13 and `-D_GLIBCXX_ASSERTIONS`:
```
stl_vector.h:1147: ... operator[](size_type) const ...: Assertion '__n < this->size()' failed.
#10 BaseSpline::evaluateSlope           BaseSpline.cpp:597   double maxg = g[mixg];
#11 BaseSpline::roughnessPenaltyIRLS    BaseSpline.cpp:123
#12 PosteriorEstimator::estimate        PosteriorEstimator.cpp:210
#14 Scores::calcPep                     Scores.cpp:1847
#15 Percolator::rescore                 Percolator.cpp:2219
```

**Fix.** After the general IRLS step, put the dropped entries back as zeros (`fillPacked`), before `limitg()`, since `LogisticRegression::limitg` uses `packedReplace`, which expects a filled vector. A `gnew` that is already filled is left untouched, so results only change where an entry had been dropped, and those were reading shifted or out-of-bounds values before. The existing `isFilled` helper moves up in the file so the new code can use it. No new test: the existing section is the regression test and fails under hardened or assertion-enabled builds.

**Tested** (RelWithDebInfo, g++ 13, `-D_GLIBCXX_ASSERTIONS`, `OMP_NUM_THREADS=3`):
- Before: `Percolator_test` aborts as above.
- After: all 16 of `Percolator*_test`, `OpenSwathPercolatorScoring_test`, `FalseDiscoveryRate_test` and `PosteriorErrorProbabilityModel_test` pass. (`Percolator_subprocess_parity_test` and `PercolatorAdapter_parity_test` finish in well under a second here, so they likely skip without an external `percolator` binary.)
- Not run: the macOS/libc++ build itself, and the TOPP tests.
